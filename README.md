# hoot-polars

`hoot-polars` is a Rust 2024 library and command-line application for reading CTRE
Phoenix 6 `.hoot` files into Polars DataFrames or Parquet. Parsing is performed
directly by this crate.

The implemented scope is HOOT compliancy 19, custom logged signals, and the
Phoenix 6 firmware-major-26 TalonFX status catalog represented in the source.
Both classic CAN and CAN FD records are supported. Other compliancy and
firmware versions are detected but are not decoded through that catalog.

## Library

```rust,no_run
use hoot_polars::HootParser;

let frame = HootParser::from_file("robot.hoot")?;
assert_eq!(frame.get_column_names()[0], "timestamp");

HootParser::process_file_batched("robot.hoot", 5_000, |batch| {
    println!("{} rows", batch.height());
    Ok(())
})?;

// Keep pass-one schema work when inspection and conversion are separate steps.
let prepared = HootParser::prepare_file("robot.hoot")?;
println!("{} supported signals", prepared.report().schema.len());
prepared.process_batched(5_000, |_batch| Ok(()))?;

// Device-grouped batches avoid materializing every global signal column.
prepared.process_narrow_batched(5_000, |batch| {
    println!("{}: {} rows", batch.group, batch.frame.height());
    Ok(())
})?;
# Ok::<(), hoot_polars::HootError>(())
```

`HootParser` provides `from_bytes`, `from_file`, `infer_schema`, and bounded
`process_file_batched` methods. Corresponding `*_selected` methods avoid
allocating unused columns for narrow analyses. `prepare_file` returns a
`PreparedHoot` that retains its memory map and schema report, so callers can
inspect pass-one results and stream data in the second traversal without
rediscovering the schema. `HootReader` exposes checked headers, physical
records, schema reports, raw identifiers and offsets, and a Polars-independent
typed update iterator.

`PreparedHoot::process_narrow_batched` is intended for database ingestion. It
groups Phoenix signals by device and custom signals together, and adds a
`source_sequence: Int64` column derived from decoded source order. Consumers
can combine the batches with a schema-unioning Parquet scan and use the sequence
to deterministically collapse equal-timestamp rows after forward filling.

The DataFrame contract is:

- `timestamp: Int64` in microseconds is the first column;
- rows are ordered by unique timestamp;
- catalog columns use simple names such as `device_1_motor_voltage`;
- custom signals retain the names stored in the input file;
- a missing update is null rather than forward-filled;
- type, units, source, device, bus, and support information remain available
  through `HootSchema`.

The facade defaults to lenient tail handling because a log may end before its
final buffered record or entropy marker is flushed. `HootReader::new` remains
strict. A bounded reorder buffer handles timestamp regressions; an update
outside the effective window is an error. Materializing APIs use the larger of
the configured minimum and the maximum regression measured during their schema
pass, while `max_buffered_rows` remains the hard memory bound.

## CLI

```powershell
cargo run -- info robot.hoot
cargo run -- info robot.hoot --semantic-stats
cargo run -- schema robot.hoot
cargo run -- convert robot.hoot robot.parquet --rows-per-batch 5000
cargo run -- repair-tail truncated.hoot repaired.hoot
cargo run -- frames robot.hoot --arbitration-id 0x02046bc0
```

Use `--tail strict` to require a complete final record and entropy terminator.
`repair-tail` writes a new canonical copy at the retained bit boundary and
refuses to overwrite either its input or an existing output. Conversion uses a
temporary file beside the destination and persists it only after the Parquet
footer is complete.

See [compatibility](docs/compatibility.md) for the supported boundary and
[format notes](docs/hoot-format.md) for the implemented byte layout.

## Tests and local data

Normal tests are hermetic and use generated data. A small synthetic fixture is
kept under `tests/fixtures/`. The ignored external-input test accepts an
authorized local `.hoot` path through `HOOT_TEST_INPUT`; robot logs and derived
data remain excluded from source control.

```powershell
$env:HOOT_TEST_INPUT = 'C:\path\to\authorized-log.hoot'
cargo test --test external_input -- --ignored --nocapture
```
